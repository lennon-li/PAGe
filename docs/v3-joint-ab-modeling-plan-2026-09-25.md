# PAGe v3 A/B timing and forecasting plan

Date: 2026-09-25
Status: revised after independent architecture review; v2 remains frozen

## Governing principle

PAGe v3 should use paired Influenza A/B surveillance to improve timing inference while preserving separate type-specific outputs.

The production-facing structure is:

`paired A/B observations -> type-specific activity/timing state -> M1-A + M1-B -> M2-A + M2-B`

Shared A/B information is context, not a replacement for separate A and B models.

V2 remains frozen except for correctness fixes and weekly refreshes. V3 research must not mutate frozen v2 artifacts, defaults, or as-issued forecast vintages.

## What changed from the original v3 plan

Independent review of the frozen v2 stack and the initial v3 proposal led to four material changes:

1. **M1 becomes explicitly type-specific.** Frozen M1-v2 is the M1-A baseline. V3 must develop a separate M1-B rather than treating one joint timing model as the timing stage.
2. **B ignition is not gold truth.** The current B ignition values are operational activity markers generated by transferring the A ignition rule to B. They are useful for exploration and gating, but they must not be used as supervised biological/expert B ignition truth.
3. **Chronological expanding-window replay is the primary historical benchmark.** LOSO remains a secondary robustness analysis. This better matches deployment governance and prevents later seasons from selecting models used on earlier seasons.
4. **Start asymmetric and simple.** The first joint-information candidate should be A-conditioned B timing, not a symmetric latent A+B phase model. A timing is already strong; historical B timing is heterogeneous and often follows A. More complex shared-phase models are deferred until the simpler candidate establishes incremental value.

A fifth implementation change follows from the review:

5. **Timing corrections should be posterior mixtures, not a separately learned confidence gate.** With only ~11 target seasons, avoid learning an additional `lambda(t)` unless later evidence justifies it. If a timing posterior is available, integrate the shape correction over that posterior so uncertainty naturally shrinks the correction toward the state baseline.

## Stage architecture

### M0-A — A ignition/activity detection

Retain frozen M0-v2 as the M0-A benchmark and operational baseline.

M0-A outputs:

- causal A ignition evidence
- activation week/posterior state
- passage-relevant A state used by M1-A/M2-A

### M0-B — B activity state, not biological ignition truth

V3 should initially treat the transferred A-rule B detector as a causal activity-state feature/gate, not a supervised ignition estimator.

M0-B outputs may include:

- whether B has reached sustained nontrivial activity
- activation/activity week if detected
- causal B growth/persistence evidence
- explicit `no_meaningful_B_activity` state where appropriate

The B activity rule can be redesigned later if prospective evidence shows the transferred rule is inadequate.

### M1-A — A peak timing

Frozen M1-v2 becomes the formal **M1-A baseline**.

V3 may test joint A/B features for A timing only as a challenger. M1-A should not be rewritten unless a strictly causal benchmark shows a stable gain over frozen M1-v2.

M1-A outputs:

- A future peak posterior
- A peak passage posterior
- calibrated A peak summaries/handoff

### M1-B — B peak timing

M1-B is the main missing timing component in v3.

The primary supervised target is **B peak timing**, not B ignition.

Develop M1-B in this order:

#### M1-B0: B-only baseline

Reuse the frozen M1-v2 peak-relative machinery where valid, but train on B trajectories/peak truth only.

Inputs are B prefix observations and a causal B activity/activation state.

Purpose: establish how well B can forecast its own peak without A information.

#### M1-B1: A-conditioned B timing

Add strictly causal A timing/state context to M1-B0, such as:

- A ignition state / activation age
- M1-A posterior mean/median/variance
- A probability peak has passed
- A probability peak is within 1/2/3 weeks
- observed A decline evidence
- A:B level/composition features
- B current level, slope and acceleration

The key question is whether A state improves B peak timing beyond B-only timing.

**Status after audited implementation:** stopped. The chronological M1-B1 experiment in `artifacts/v3-m1-b1-a-conditioned-v1/` was worse than B-only M1-B0 and worse than a no-A calendar-prior control. The result was robust to the prespecified bandwidth/mixture sensitivities. Do not promote or extend this additive A-to-B lag branch.

#### M1-AB2: paired template/shared-phase challenger

Only if a future, independently motivated joint-information hypothesis establishes value. The failed M1-B1 experiment does **not** justify proceeding to M1-AB2. This branch is currently deferred/stopped.

A and B may share phase evidence, but their timing coordinates remain separate.

#### Deferred: formal latent state-space phase model

Do not start here. Eleven target seasons do not support a high-dimensional latent model without very strong evidence from simpler candidates.

Keep four explicit forecast tasks:

- M2-A +1
- M2-A +2
- M2-B +1
- M2-B +2

A and B forecast heads remain separate.

### M2-A

Start from frozen v2 A state forecasts and M1-A timing handoff.

Only add joint/B context if historical causal evaluation shows incremental value.

### M2-B

Start from a B state-only baseline, then test M1-B timing information.

Compare:

1. B state-only
2. B state + B-only M1-B timing
3. B state + A-conditioned M1-B timing
4. paired-template timing only if earlier steps justify it

## Timing-informed forecast correction

Do not initially fit an extra free `lambda(t)` confidence model.

Preferred form:

`forecast = state forecast + E[timing/shape correction | timing posterior]`

When the timing posterior is diffuse, posterior averaging should naturally shrink the correction. When it is concentrated, the timing correction becomes stronger.

Required ablations:

- state-only forecast
- v2-style hard timing gate
- posterior-mixture timing correction
- oracle timing diagnostic, evaluation only

## Primary validation contract

### Primary: chronological expanding-window replay

This is the headline historical benchmark.

For each eligible test season `S`:

- train/tune only on seasons strictly earlier than `S`
- freeze all thresholds, hyperparameters, feature definitions and calibration inside the training set
- replay every test-season origin causally using only weeks available through that origin

A fixed minimum number of prior training seasons must be specified before scoring. Seasons before that minimum are initialization/training only and are not headline test seasons.

### Secondary: LOSO sensitivity

Run season-level LOSO after the chronological benchmark to assess cross-season stability.

LOSO is not the primary model-selection benchmark because it lets future seasons inform models evaluated on earlier seasons.

### No random weekly splits

Weekly rows from the same season are strongly dependent. Random row splitting is prohibited.

### Per-origin causality

At origin `t`, predictors may depend only on information released through `t`.

Retrospective peak curves, completed-season normalization, future denominators, future revisions, and final timing labels are targets/audit information only and must never enter runtime features.

## Leakage test suite

The benchmark harness must include explicit tests:

1. **Future perturbation test:** modify data after origin `t`; features and predictions at `t` must remain identical.
2. **Held-out season isolation:** changing later/test-season truth must not alter training artifacts.
3. **Training-season boundary test:** chronological folds must contain only seasons strictly earlier than the test season.
4. **Retrospective truth separation:** peak/ignition truth columns may appear only in target/scoring objects.
5. **Revision/vintage separation:** as-issued forecast artifacts remain distinct from revised-history reruns.
6. **Observation-regime audit:** regime indicators may be predictors, but source-vintage identity must not become a disguised season identifier.

## B-specific evaluation policy

B is heterogeneous and may have weak/flat seasons.

Primary B timing target:

- B peak timing when a meaningful B peak exists

Separate B activity/no-activity evaluation:

- whether a season/prefix contains enough B activity to justify timing correction

Current transferred B activity weeks are exploratory annotations and may be used for causal activation/gating experiments, but **not as gold supervised B ignition labels**.

A model must be allowed to return no meaningful B timing event rather than being forced to assign one.

## Frozen-v2 comparison

Maintain two comparison views:

1. **Governance view:** frozen/as-issued v2 artifacts and metrics remain untouched.
2. **Matched-data research view:** replay frozen v2 algorithms on the same canonical v3 observation panel where feasible, clearly labeled as a research rerun.

This separates algorithmic changes from data-vintage/target changes.

## Observation-regime and robustness checks

Report results separately where estimable for:

### Phase 1 — M1 timing benchmarks

1. Reproduce frozen M1-A behavior on the canonical research panel where possible.
2. Build chronological benchmark harness.
3. Implement M1-B0 B-only peak timing using the smallest adaptation of M1-v2 mechanics.
4. Implement M1-B1 A-conditioned B timing. **Completed; branch stopped after failing against B0 and the no-A control.**
5. Build a calibrated B-only M1-B baseline using only B data and the frozen M1-v2 timing machinery. **Completed; scalar calibration stopped after audited chronological evaluation. Raw M1-B0 is retained for peak location.**

7. Re-run raw B-only M1-B0 under that policy. **Completed. Five scored chronological seasons: season-balanced MAE 1.6573 weeks, early-weighted MAE 1.6580, mean 90% coverage 0.80, with 2022-23 retained as the material failure case.**

9. **Freeze raw pandemic-excluded M1-B0 as the B peak-location model for shadow work. Do not run another historical passage-threshold search on these five scored seasons. Continuous `prob_peak_passed` may be carried only as shadow uncertainty / a causal continuous M2-B feature.**

### Phase 2 — optional paired timing model

Deferred. The first audited cross-type timing experiment did not demonstrate incremental A-to-B timing value, so do not start a paired-template or latent shared-phase timing model from this result.

Do not build a full latent state-space model unless the paired-template model leaves a documented failure mode that justifies the extra complexity.

1. Establish state-only A/B +1/+2 baselines.
2. Add M1-A timing to M2-A.

### Phase 5 — full-history fit and prospective v3 shadow

After historical candidate selection is frozen:

1. fit M1-A/M1-B and M2-A/M2-B on all completed seasons through 2025-26;

5. preserve as-issued v3 forecast vintages separately from revised-history reruns;

## Promotion criteria

A v3 component is promoted only if it shows:

- causal validity and reproducibility
- meaningful out-of-season gain over the appropriate baseline
- no unacceptable worst-season degradation
- stable behavior across observation regimes
- calibrated uncertainty where claimed
- interpretable no-event/fallback behavior
- prospective shadow evidence before replacing v2 defaults

Promotion is component-wise. M1-B can advance without replacing M1-A; M2-B can advance without changing M2-A.
