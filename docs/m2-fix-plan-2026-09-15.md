## Phase 1 - Correctness fixes (block everything else)

1. **Season-held-out upstream M1 for M2 rows and gate (High).** For each inner season s, generate
   M1 walk-forward predictions from an M1 reference fitted without s (reuse the M1 LOSO refs from
   tuning where identical). `m2_subset_correction.R:601`, `nested_season_evaluation.R:110`.
2. **Calendar length independent of coverage (High).** Derive `nW_true` from the season calendar
   (MMWR weeks in start year), never from observed max; fail if absent. `pipeline_training.R:325`,
   `m1_loso.R:783`. Regression test: partial season week 28 -> aligned 29.
3. **Identical preprocessing in M1 tuning and fitting (High).** Same `k_deriv` (20) and
   `peak_weight_boost` (3) in tune and fit. `pipeline_training.R:300,542,676`.
4. **M0 contract (Medium).** Honor `use_cls = FALSE` in voting; keep missed detections as missing
   (not `w_max`); apply D2 loss. `m0_training.R:654,673,930`; `timing_pipeline_v2.R:161`.
5. **M1 init weights (Medium).** Remove double N weighting in initialization GLMs. `m1_fit.R:162,185`.
6. **Partial-season handling (High).** Implement D1 with explicit censoring flags.
7. **Reproducibility (Medium).** Record RNG state/seed, full dependency versions (incl. gratia),
   post-training manifest, bounded warning summary.

Each fix: minimal patch, unit/regression test, equivalence test showing unaffected paths unchanged.

## Decisions recorded 2026-09-15 (Lennon)

- **Fully nested inner gate** (Liz finding 4): gate season s uses M1 without s; training rows of r != s use M1
  without r and s; nothing fitted on s enters the correction evaluated on s.
- **Scoring weights** (D3): pre-ignition 0, rise 2, turning window peak-1..peak+3 3, decline 1.
- **Phase 3 terms**: tau (target week - M1 peak estimate at origin, capped +-6) and peak-CI confidence scaling; staged
  search; off always in grid; gate-selected.
- **Grids for the new cycle** (prior-cycle-informed, declared in PROTOCOL v2.0; boundary expansion kept on):
  M0 unchanged (36); M1 FIXED k_ref = 30, slope_weight = 16 (superseded the 20-spec grid the same day: M1 surface spans
  0.16-0.18 weeks, k_ref ranking flips when one season is added, 30/40/50 equivalent); M2 intercept {F,T} x k_z {0,3,4,5} x
  k_u {0,7,8,9} x k_d {0,3,4,5,6,7} (192). Evidence: Wei survey (scratchpad wei_hyper_report.md): M1 is 72-78% of
  wall time; all h1 M2 specs within 0.0012; k_u = 8 won in all four horizon-runs.
- **User guidance**: recommend users start from a modest grid and expand from boundary results (tuning playbook),
  rather than exhaustive grids.
- **Compute**: Asgard + BCC after an equivalence check; SciNet (weekly data only, never daily) only if needed.
- **Framework principle**: hyperparameters are never removed; recipes fix them with single-value grids, so other
  viruses can tune them. The nested gate re-runs selection for every axis a recipe tunes (M0 here; M1 only when a user
  supplies a multi-value grid). Sensitivity recipe: k_ref = 20, slope_weight = 12.
- **M0 audit (2026-09-15)**: M0 tuning is ~13 s/run (no speed case). Prior-cycle surface was degenerate (old loss gave
  0 to early errors <1 week; p_thr/prev_thr ties; identical selection in every fold). Queued after commit: pre-freeze
  M0 surface check under the new symmetric loss (Wei; packet wei_m0surface_packet.md) to decide fixing p_thr/prev_thr
  and a deterministic tie-break rule.
